# How Herdr remote attachment differs from Kiwa

This investigation reads the official `herdrdev/herdr` sources at commit [`2563803dca97c040beaf3dc3acdcb5a3221b4238`](https://github.com/herdrdev/herdr/commit/2563803dca97c040beaf3dc3acdcb5a3221b4238). The package declares version `0.9.3` in [Cargo.toml, lines 1–5](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/Cargo.toml#L1-L5). Sources were fetched through authenticated `gh api` over HTTPS into `/tmp/herdr-investigation-2563803/herdrdev-herdr-2563803`. No Herdr binary, remote host, or test was run. Statements about behavior below describe source code, not observed runtime results.

## The CLI selects a remote launch rather than an SSH terminal session

The supported form is `herdr --remote <ssh-target> [--session <name>] [--remote-keybindings local|server] [--handoff]`. Both `--remote target` and `--remote=target` are parsed. Targets must be nonempty and cannot begin with `-`. Duplicate remote and keybinding flags fail. `--remote-keybindings` defaults to `local` and requires `--remote`. Parsing stops at `--`. See [remote/args.rs, lines 1–127](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/args.rs#L1-L127).

`--session name` and `--session=name` are removed before default-launch dispatch and select the active session. Remote launch does not combine with another subcommand. For example, `herdr --remote host session attach name` is not the remote syntax. See [session.rs, lines 56–102](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/session.rs#L56-L102) and [main.rs, lines 535–556](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/main.rs#L535-L556).

## Bootstrap matches capabilities, not necessarily versions

Herdr prepares a remote executable, checks the existing server, starts an SSH stdio bridge, and launches the local client. A stopped server is not started by the readiness check itself. The remote client bridge starts or attaches to it. See [attach.rs, lines 41–93](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L41-L93), [lines 1948–1997](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1948-L1997), and [lines 2379–2394](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L2379-L2394).

The bootstrap detects Linux or macOS on x86_64 or aarch64 through `uname`. It also probes Windows, including ARM64 through an x86_64 package. POSIX discovery checks PATH and known local-bin, Homebrew, mise, and Nix locations. It excludes mise shims and requires absolute executable paths. Windows discovery checks PATH, current-user Herdr processes, and the active package junction. See [attach.rs, lines 1526–1780](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1526-L1780).

An installed remote binary does **not** have to equal the local version. The acceptance predicate compares endpoint protocol generation, requires `remote_host_bridge` on Windows, and adds surface-interest, presentation-effects-fence, and health-check requirements when saved-machine federation needs them. Parsed version and legacy protocol fields are not compared by this predicate. Without an override, the first acceptable candidate is reused. See [attach.rs, lines 2172–2210](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L2172-L2210), [lines 1309–1360](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1309-L1360), and [lines 1411–1447](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1411-L1447).

Downloaded releases do target the local build identity. Stable selection finds the local version in the current or historical release manifest. If the stable manifest supplies a protocol, it must match `CURRENT_PROTOCOL`; a missing protocol is accepted. Preview selection requires the local build ID and an exact protocol match rather than selecting the latest preview. See [attach.rs, lines 633–648](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L633-L648) and [lines 2498–2567](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L2498-L2567).

Normal installation requires terminal stdin and an approval prompt, `[Y/n]`, whose empty answer approves. A disruptive installation instead asks an explicit install-and-stop question, `[y/N]`, warning that shells, agents, dev servers, and tests stop. EOF or cancellation does not approve installation. See [attach.rs, lines 2592–2643](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L2592-L2643) and [lines 1999–2112](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1999-L2112).

`HERDR_REMOTE_BINARY` forces installation from a supplied nonempty regular file. POSIX can otherwise copy the local executable when its platform matches and it is not package-manager-owned. Other cases download an asset. Windows requires a complete ZIP package with the app-local ConPTY runtime rather than a single executable. See [attach.rs, lines 1818–1915](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1818-L1915) and [lines 1450–1467](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1450-L1467).

POSIX installation streams the binary through SSH to `$HOME/.local/bin/herdr.tmp.$$`, applies mode 755, and moves it to `$HOME/.local/bin/herdr`. A post-install capability check verifies the installed executable. Windows uses SCP and an embedded PowerShell installer with `-ExecutionPolicy Bypass`, explicit package identity, and hash arguments. See [attach.rs, lines 891–1026](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L891-L1026), [lines 1096–1107](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1096-L1107), and [lines 1372–1386](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1372-L1386).

Version inequality alone does not restart a running server. Restart reasons are endpoint generation, required surface-interest support, required health checks, and detached-daemon support. Explicit `--handoff` can use live handoff when the server supports it. The handoff command passes the prepared executable's expected protocol and version; failure falls back to restart handling. Required compatibility restarts need approval. A detach-only restart can be declined or deferred in nonterminal operation. See [restart_policy.rs, lines 16–62](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/restart_policy.rs#L16-L62), [attach.rs, lines 427–455](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L427-L455), and [lines 2278–2414](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L2278-L2414).

## SSH authenticates transport, while manifests supply download hashes

Interactive bootstrap uses `ssh -T`, not a remote PTY. Managed SSH and SCP enable compression. The generated configuration includes user and system SSH configuration, adds keepalive defaults of 15 seconds and four missed replies, and uses scoped OpenSSH connection multiplexing where supported. A managed-config creation failure falls back to plain SSH. Ordinary interactive bootstrap does not itself force strict host-key checking or noninteractive authentication options. Its effective authentication and host-key policy follows OpenSSH configuration and defaults. See [attach.rs, lines 780–846](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L780-L846), [lines 1227–1269](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1227-L1269), and [lines 2936–2978](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L2936-L2978).

Saved-machine background connections explicitly set `BatchMode=yes`, `NumberOfPasswordPrompts=0`, `StrictHostKeyChecking=yes`, `ConnectTimeout=10`, `ConnectionAttempts=1`, and keepalives of 15 seconds with four missed replies. Captured noninteractive SSH commands have a 15-second process timeout. Explicit interactive authentication recovery requires managed configuration and multiplexing, retains strict host-key checking, disables askpass, and permits three password prompts. Unknown or changed host keys are not classified as recoverable authentication failures. See [attach.rs, lines 704–775](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L704-L775), [lines 810–889](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L810-L889), and [lines 1209–1225](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1209-L1225).

Release manifests come from `https://herdr.dev/latest.json` or `https://herdr.dev/preview.json`. Download commands use curl with `-sfL`, so redirects are followed. This code does not restrict manifest-provided asset URLs or redirects to HTTPS-only protocols. Stable assets require a SHA-256 from the asset object or release checksum map. Preview checksums are optional, and verification occurs only when a hash is present. See [attach.rs, lines 33–34](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L33-L34) and [lines 2442–2567](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L2442-L2567).

The verifier requires 64 hexadecimal characters and rejects a file whose SHA-256 differs. There is no detached-signature or signed-manifest verification in this download path. The checksum proves agreement with the fetched manifest, not authenticity independent of that manifest. A custom Windows package receives a locally computed hash rather than an externally authenticated reference hash. See [checksum.rs, lines 9–39](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/checksum.rs#L9-L39) and [attach.rs, lines 1457–1463](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L1457-L1463).

A separate Unix SSH-agent registration worker observes `SSH_AUTH_SOCK`, registers it through the server API when supported, and retries initial API readiness or a lost registration connection every 100 milliseconds. This is not the UI reconnect loop and is not evidence that Herdr unconditionally enables OpenSSH agent forwarding. See [ssh_agent.rs, lines 16–56](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/ssh_agent.rs#L16-L56) and [lines 71–127](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/ssh_agent.rs#L71-L127).

## The client renders surfaces received over SSH

The source establishes this process path:

```text
Local outer terminal
  <-> local Herdr client
  <-> private local IPC bridge
  <-> ssh -T stdin/stdout
  <-> remote Herdr remote-client-bridge
  <-> remote daemon client socket
  <-> remote pane PTYs and child programs
```

The local bridge starts `ssh -T` with piped stdin and stdout and copies bytes between SSH and a local IPC stream. It discards shell startup output until a ready-marker line before binary decoding. The remote `remote-client-bridge` connects to the remote daemon's client socket, starting the daemon when needed. No remote SSH PTY carries the UI. See [attach.rs, lines 3037–3133](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L3037-L3133), [lines 3234–3274](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L3234-L3274), and [host.rs, lines 6–63](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/host.rs#L6-L63). Unix forwarding copies in both directions and half-closes the socket's write side when upload finishes. See [unix_common.rs, lines 158–207](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/platform/unix_common.rs#L158-L207).

Each wire message has a four-byte little-endian payload length followed by bincode data using `bincode::config::standard()`. The reader checks length before allocation, handles partial reads, and rejects trailing undecoded bytes. The private protocol version is `22`, while client-owned shells negotiate endpoint generation `1` and the codecs `shell.snapshot.v1`, `shell.surface.v1`, `shell.input.semantic.v1`, and `shell.blob.v1`. Named endpoint controls contain JSON strings inside the binary envelope. See [wire.rs, lines 19–35](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/protocol/wire.rs#L19-L35), [lines 1656–1730](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/protocol/wire.rs#L1656-L1730), and [endpoint.rs, lines 1–179](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/protocol/endpoint.rs#L1-L179).

Handshake acceptance checks generation and the selected codecs, not build-version equality. The server rejects malformed hello data, unsupported generations, missing required codecs, and unsafe geometry. See [handshake.rs, lines 200–291](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/handshake.rs#L200-L291) and [client_transport.rs, lines 737–800](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/client_transport.rs#L737-L800).

The daemon owns pane execution and terminal state. It sends pane surfaces, projection revisions, metadata, popup information, and graphics. The local client composes the sidebar and unavailable-state UI around those surfaces. UI actions enqueue endpoint API requests, while pane input uses semantic events. Clipboard writes and safe URL opening happen locally. See [render.rs, lines 813–827](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/headless/render.rs#L813-L827), [composition.rs, lines 23–177](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/shell/composition.rs#L23-L177), and [shell_runtime.rs, lines 3–55](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/shell_runtime.rs#L3-L55).

`--remote-keybindings local` selects the local client's remote-local keybinding source. `server` selects the endpoint's keybindings, negotiated through hello and server state. The option changes keybinding ownership, not where pane programs run. See [handshake.rs, lines 35–47](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/handshake.rs#L35-L47) and [shell/config.rs, lines 175–190](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/shell/config.rs#L175-L190).

A dedicated endpoint writer owns partial writes, cancellation, and bridge lifetime. Its queue permits 256 batches and 64 MiB, and its write timeout is five seconds. This separates a slow endpoint's writes from the UI and other endpoints. See [writer.rs, lines 12–79](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/endpoint/writer.rs#L12-L79). Local IPC uses Unix filesystem sockets or Windows namespaced local sockets backed by named pipes. Private Windows listeners apply an owner-and-SYSTEM security descriptor. See [ipc.rs, lines 36–173](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/ipc.rs#L36-L173).

## Terminal features cross explicit protocol boundaries

Copy writes through the local clipboard output path. Client-shell clipboard actions call `selection::write_osc52_bytes`; forwarded server clipboard payloads are base64-decoded before that same function. Invalid base64 is rejected. This source path does not prove that every local terminal grants clipboard access. See [shell_runtime.rs, lines 35–37](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/shell_runtime.rs#L35-L37) and [clipboard_forwarding.rs, lines 3–15](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/clipboard_forwarding.rs#L3-L15).

Image paste uploads bytes with `ClipboardImage`, targeting a pane and carrying an extension. The client rejects images larger than 16 MiB. The server stages the image in its own temporary directory and supplies a remote path for paste. Unix staging uses directory mode 0700 and file mode 0600. Disconnect removes that client's staged images, so pasted image paths are not guaranteed to survive disconnection. See [clipboard_images.rs, lines 12–43](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/clipboard_images.rs#L12-L43), [clipboard_image.rs, lines 13–112](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/clipboard_image.rs#L13-L112), and [headless.rs, lines 953–957](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/headless.rs#L953-L957). The server also has a direct-byte input path that recognizes complete bracketed paste separately from ordinary input bytes. It must not be confused with semantic endpoint input. See [pane_input.rs, lines 187–200](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/pane_input.rs#L187-L200).

Keyboard events can carry press, repeat, release, modifiers, generated text, shifted codepoints, release tracking, and physical-key information. The server asks the host client to report all keys when the focused child's keyboard protocol needs that mode. See [wire.rs, lines 155–183](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/protocol/wire.rs#L155-L183) and [render.rs, lines 150–194](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/headless/render.rs#L150-L194). Actual key fidelity remains dependent on the local terminal and was not tested.

Mouse capture follows configuration and child-terminal requirements. Pixel mouse support requires exact cell geometry and a Unix client. The server uses pixel coordinates only when the target runtime enables SGR pixel mouse; otherwise, accompanying cell coordinates provide a fallback. SSH does not itself supply exact cell geometry. See [render.rs, lines 36–96](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/headless/render.rs#L36-L96), [handshake.rs, lines 184–207](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/handshake.rs#L184-L207), and [pane_input.rs, lines 225–294](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/pane_input.rs#L225-L294).

Host terminal theme information travels as explicit client state. The client can query the local terminal, record `ClientShellHostTheme`, and forward updates during endpoint activation. This is evidence of theme propagation, not an interoperability guarantee for every terminal's color-query responses. See [shell_runtime.rs, lines 735–779](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/shell_runtime.rs#L735-L779).

Remote graphics are supported as assets and placements in pane surfaces. The client composes them using surface origins, cell dimensions, visibility, and occlusion. Direct graphics that reference server files require a shared filesystem, exact cell dimensions, and an allowed terminal profile. Remote-client, SSH, tmux, and screen environments block that direct profile. A local bridge socket does not make a saved SSH endpoint filesystem-local. See [graphics.rs, lines 48–83](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/shell/graphics.rs#L48-L83) and [handshake.rs, lines 60–109](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/handshake.rs#L60-L109).

Normal frames are capped at 2 MiB and graphics frames at 32 MiB. The server trims inline graphics from oversized surfaces. An asset that cannot fit stays absent until a later scene change rather than being retried continuously. See [wire.rs, lines 22–32](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/protocol/wire.rs#L22-L32) and [render.rs, lines 836–900](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/headless/render.rs#L836-L900). Graphics fidelity was not exercised.

## Saved endpoints reconnect without restarting pane programs

There is an implemented saved-SSH reconnect path, not merely a documented promise. `connect_saved_ssh` validates the destination, finds an installed executable, starts a new noninteractive bridge, and connects to local IPC. The supervisor then performs a new endpoint handshake with the surface initially inactive. This path uses an existing installation rather than an unattended reinstall. See [saved.rs, lines 15–40](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/saved.rs#L15-L40) and [supervisor.rs, lines 265–335](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/endpoint/supervisor.rs#L265-L335).

SSH retry delay starts at 500 milliseconds and doubles to a maximum of 120 seconds. Local retries cap at 30 seconds. A brief successful SSH connection does not reset backoff; remaining online for at least 60 seconds does. SSH endpoints needing attention are rechecked every 30 seconds, and disabled endpoints do not retry. Generation checks reject stale connection results and disconnect events. See [supervisor.rs, lines 11–14](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/endpoint/supervisor.rs#L11-L14), [lines 191–370](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/endpoint/supervisor.rs#L191-L370), and [client/mod.rs, lines 2182–2193](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/mod.rs#L2182-L2193).

Health checks probe after five seconds without incoming traffic and expire an unanswered probe after ten seconds. Any incoming message satisfies the outstanding probe. Initial snapshot readiness has its own ten-second deadline. These are code thresholds, not measured recovery times under a silent network blackhole. See [health.rs, lines 3–58](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/endpoint/health.rs#L3-L58).

On disconnect, the client retires graphics, cancels pending endpoint requests, handles activation rollback, and shows an unavailable state when the failed endpoint was active. It clears that endpoint's host mouse effects. The server removes the client connection, releases held input, focus, and geometry ownership, and cleans staged images. This client removal does not itself shut down pane processes. See [shell_runtime.rs, lines 519–569](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/shell_runtime.rs#L519-L569), [client/mod.rs, lines 2194–2239](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/client/mod.rs#L2194-L2239), [headless.rs, lines 931–1011](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/headless.rs#L931-L1011), and [lines 2603–2612](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/server/headless.rs#L2603-L2612).

The local bridge gives upload failure, local closure, or download completion a 250-millisecond grace period before killing the SSH child. Supported remote bridges can enable a 60-second inactivity watchdog that exits the dedicated bridge process, not the daemon. See [attach.rs, lines 3134–3208](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/remote/attach.rs#L3134-L3208) and [remote_bridge.rs, lines 8–49](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/platform/remote_bridge.rs#L8-L49).

These findings establish the saved-endpoint supervisor's reconnect implementation. They do not establish identical recovery for every legacy or direct-launch mode, exact wall-clock recovery, or successful terminal interoperability. Those questions need separate runtime tests.

## Kiwa can use a remote PTY without adopting Herdr's protocol

The Kiwa comparison is pinned to [`5b2bc7651b5dd9038bfa95c8c26c016738460692`](https://github.com/txchen/kiwa/commit/5b2bc7651b5dd9038bfa95c8c26c016738460692). The local ADRs and source files were inspected directly. Their behavior was not exercised in a remote session.

Kiwa's [ADR 0004](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/docs/adr/0004-server-owns-the-outer-terminal.md#L3-L22) makes the server read and write the outer terminal directly. The client sends its stdin descriptor with hello and then uses the socket for control messages and resize or detach signals. See [client.zig, lines 105–145](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/client.zig#L105-L145).

A network socket tunnel alone cannot preserve this contract. Descriptor transfer uses Unix ancillary data, and reopening the descriptor requires a character terminal. The server rejects attachment without the descriptor. See [sys.zig, lines 247–327](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/sys.zig#L247-L327) and [server.zig, lines 526–566](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L526-L566).

The smallest proposed remote access method is `ssh -t host 'kiwa'`. With an interactive local terminal and server permission, SSH allocates a remote PTY. The remote Kiwa client then passes that remote terminal descriptor to its remote server through the existing local Unix socket. This is an architectural inference, not a tested command. It requires Kiwa to be installed and available to the remote shell. The local machine needs SSH, not a local Kiwa installation. Protocol-version compatibility concerns the two remote Kiwa processes, not a local binary. Kiwa currently uses protocol version `4`, checked during attachment. See [protocol.zig, lines 4–32](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/protocol.zig#L4-L32) and [server.zig, lines 526–534](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L526-L534). Configuration, files, Git operations, and pane shells belong to the remote machine. It does not copy local configuration or bootstrap a matching binary.

Kiwa attachment replaces the previous client rather than creating a second concurrent outer terminal. Its server stops terminal writes and closes the terminal handle before sending detach. See [server.zig, lines 526–566](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L526-L566) and [server.zig, lines 1680–1748](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L1680-L1748).

The socket directory is private, the server creates its resources with `umask 077`, and the client verifies the server's peer UID. The server starts through `setsid` and a double fork. Stdin and stdout are redirected to `/dev/null`, while stderr goes to the server log. See [paths.zig, lines 37–100](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/paths.zig#L37-L100), [server.zig, lines 1796–1821](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L1796-L1821), and [client.zig, lines 163–218](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/client.zig#L163-L218).

Terminal EOF detaches the client while pane programs remain. Socket EOF drops the connection rather than killing the session. The source includes a terminal hangup and reattach test, but this investigation did not execute it. See [server.zig, lines 396–438](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L396-L438), [server.zig, lines 1741–1748](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L1741-L1748), and [tests/e2e.zig, lines 625–646](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/tests/e2e.zig#L625-L646). SSH loss detection timing is unknown. Reconnection in this proposal is manual: rerun the SSH command to attach to the surviving server. Kiwa's client exits on socket loss rather than retrying, as [client.zig, lines 120–145](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/client.zig#L120-L145) shows. Remote logout policies that kill session processes could still terminate the server. An abrupt SSH failure could also prevent the remote client's restoration sequences from reaching the local outer terminal.

Reconnect must not be described as killing the server. Kiwa's [README.md, lines 115–125](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/README.md#L115-L125) warns that an upgrade through server termination stops pane programs. Layout restoration starts new shells rather than preserving those processes.

Kiwa enables outer-terminal mouse, paste, and focus modes in [client.zig, lines 9–20](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/client.zig#L9-L20). Clipboard output uses OSC 52 in [server.zig, lines 1291–1310](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L1291-L1310). The server also probes kitty keyboard support, left and right margins, and DA1. A relay must carry terminal replies back to the server, not just keystrokes. See [server.zig, lines 63–68](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/server.zig#L63-L68). Whether each local terminal accepts these sequences through a particular SSH setup remains untested.

## The smallest Kiwa path preserves server-side composition

The following options are proposed designs, not implemented or runtime-verified features.

- Use `ssh -t host 'kiwa'` first. It places both Kiwa processes on the remote host and preserves ADR 0004. It provides remote access to one remote session, not a local sidebar that combines local and remote workspaces. Authentication remains OpenSSH's responsibility. Remote installation is a prerequisite.
- Do not forward the existing Unix socket as an attachment solution. SSH transports bytes, not a usable cross-host terminal descriptor. A pipe cannot replace the descriptor either. Kiwa requires terminal stdin and reads dimensions from stdout, as [client.zig, lines 59–84 and 148–151](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/client.zig#L59-L151) shows. `ssh -T host kiwa` therefore does not provide the required terminal.
- If a local launcher later needs a non-PTY SSH data channel, a remote PTY adapter could retain the current server contract. The helper would keep a PTY master, pass the slave locally to the remote server, and relay master bytes over SSH. It would need raw modes, initial size, resize messages, bounded bidirectional queues, terminal-query replies, and detach ordering. PTY termios is shared even when Kiwa reopens the slave with independent file flags.
- A native byte-relay transport would instead add explicit input and encoded terminal-output messages. It could keep composition and VT state on the server. The current [protocol tags and message union](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/protocol.zig#L23-L46) contain no such data path. This would revisit [ADR 0004](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/docs/adr/0004-server-owns-the-outer-terminal.md#L3-L22), while retaining the server-side composition decision in [ADR 0003](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/docs/adr/0003-server-composes-frames.md#L1-L19). It does not require copying Herdr's client-owned sidebar and semantic surface protocol.

A forwarded control socket also changes peer-credential meaning. The peer becomes the forwarding process. Kiwa's `kill-server` obtains and signals that peer's PID, so it must not be assumed to target the actual server through a forwarded endpoint. See [client.zig, lines 222–241](https://github.com/txchen/kiwa/blob/5b2bc7651b5dd9038bfa95c8c26c016738460692/src/client.zig#L222-L241).

My recommendation is ordinary SSH PTY access before any new transport. If a later requirement explicitly needs a local client, compare a remote PTY adapter with a server-owned byte relay. Herdr's automatic bootstrap, stable endpoint negotiation, saved-endpoint supervision, and local UI composition solve a broader problem than Kiwa's current remote-session access need.

Runtime questions remain open: Linux and native macOS PTY reopening, silent network failure detection, resize delivery, terminal restoration after abrupt loss, clipboard permissions, keyboard fidelity, and slow-link backpressure. No latency, CPU, bandwidth, or interoperability claim follows from this source inspection.
